# 智能发现“展示报告”功能设计规格

日期：2026-09-01

状态：已批准

范围：`combine_up_and_source` 后端与 `CombinedDiscovery` 前端

## 1. 背景与目标

现有“智能发现”会根据用户兴趣推荐博主和平台，再调用自定义源能力聚合内容。结果包含推荐信息、批次状态和原始内容条目，但仍是按来源组织的发现结果，用户需要自行判断内容与兴趣关键词的关系，也缺少稳定的阅读顺序。

本功能在一次已经完成的智能发现结果之上生成“展示报告”。用户只选择希望看到的信息量，系统负责：

- 从发现结果中筛选高相关内容；
- 解释每位博主、每个平台和每条内容与用户兴趣的关系；
- 自动判断报告意图并选择固定结构；
- 按认知或决策顺序组织内容；
- 以报告看板展示，并支持浏览器打印/PDF和复制 Markdown。

报告生成不得重新执行推荐或抓取，必须基于不可变的智能发现快照。

## 2. 范围与非目标

### 2.1 首版范围

- 智能发现成功后持久化不可变快照，并返回 `discovery_id`；
- 提供基于 `discovery_id` 和信息量生成报告的接口；
- 使用确定性规则完成清洗、去重、初筛和来源多样性控制；
- 使用 Codex 完成语义相关度、关系说明、标签、意图分类、阶段分配和总览总结；
- Codex 不可用时生成确定性的基础报告；
- 在“智能发现”模块内提供“发现结果 / 展示报告”两个视图；
- 支持页面看板、浏览器打印/PDF和复制 Markdown。

### 2.2 非目标

- 不重新抓取或刷新智能发现结果；
- 不提供用户手动选择报告结构；
- 不用推荐博主或推荐平台占用内容条数额度；
- 不为凑足条数加入低相关内容；
- 不提供服务端 PDF 生成；
- 不提供报告历史列表或跨设备同步；
- 不自动删除快照和报告。

## 3. 用户流程

1. 用户输入兴趣并完成一次智能发现。
2. 后端保存发现快照，响应中增加 `discovery_id`。
3. 前端展示报告工具栏，默认选择“标准（10 条）”。
4. 用户可选择：
   - 精简：5 条；
   - 标准：10 条，默认；
   - 详细：20 条；
   - 自定义：1–30 条。
5. 用户点击“生成展示报告”。
6. 前端展示“清洗结果 → 语义分析 → 组织报告”的阶段状态。
7. 后端读取对应快照、生成或复用报告并持久化。
8. 前端自动切换到“展示报告”视图。
9. 用户可以返回“发现结果”、打印/保存 PDF，或复制 Markdown。

如果报告生成失败，已完成的智能发现结果必须继续保留和可浏览。

## 4. 总体架构

采用“不可变快照 + 确定性规则 + Codex 语义编排 + 确定性降级”的混合架构。

```text
智能发现请求
    |
    v
CombinedDiscoveryService.discover
    |
    +--> 返回现有发现结果
    |
    +--> DiscoveryStorage 原子写入 discovery.json
              |
              v
        discovery_id 返回前端
              |
              v
用户选择 amount 并生成报告
              |
              v
DiscoveryReportService
    |
    +--> 校验并读取不可变快照
    +--> 标准化、去重、规则评分、候选截断
    +--> Codex 语义分析与结构化输出
    +--> Schema 与 item_id 边界校验
    +--> 相关度阈值与来源比例选择
    +--> 固定阶段排序
    +--> 生成 report.json 与 report.md
    |
    +--> Codex 失败时生成 deterministic fallback
```

职责边界：

- `CombinedDiscoveryService`：仍负责推荐和内容发现；成功后交给存储层保存。
- `DiscoveryStorage`：负责快照和报告的路径、安全读取、原子写入与幂等复用。
- `ReportCandidateBuilder`：标准化内容、生成稳定 `item_id`、去重并计算规则分。
- `ReportSemanticAnalyzer`：封装 Codex 提示、解析和语义结果校验。
- `DiscoveryReportService`：编排候选、语义结果、阈值、多样性、排序和降级。
- `MarkdownRenderer`：仅从已经校验的报告对象确定性生成 Markdown。

## 5. 存储设计

目录结构：

```text
data/combined_discovery/<discovery_id>/
├── discovery.json
└── reports/
    └── <report_id>/
        ├── report.json
        └── report.md
```

约束：

- `discovery_id` 使用 UUID4；
- `discovery.json` 写入后不再修改；
- 写入使用同目录临时文件加原子替换，避免进程中断留下半个 JSON；
- 路径参数必须经过格式校验，不能直接拼接任意用户输入；
- 首版不自动过期或清理，数据仅由维护者手动删除；
- 报告不包含 API key、请求头或其他凭据。

发现快照包装格式：

```json
{
  "schema_version": 1,
  "discovery_id": "uuid",
  "created_at": "ISO-8601 UTC",
  "status": "completed",
  "result": {
    "query": "机器学习",
    "keywords": ["机器学习", "Python"],
    "recommendation": {},
    "source_inputs": [],
    "batches": [],
    "summary": {},
    "warnings": []
  }
}
```

相同 `discovery_id + amount + report_schema_version` 的请求使用稳定键生成 `report_id`，如果报告文件已经完整存在则直接复用。这样可以避免重复模型调用，并保证同一快照、同一信息量的报告排序稳定。报告规则或 Schema 升级时提升 `report_schema_version`，即可生成新版本。

## 6. API 设计

### 6.1 智能发现

保留现有接口：

```http
POST /api/combined-discovery/run
```

现有响应顶层增加：

```json
{
  "discovery_id": "8da5...",
  "query": "机器学习",
  "keywords": ["机器学习"],
  "recommendation": {},
  "source_inputs": [],
  "batches": [],
  "summary": {},
  "warnings": []
}
```

只有发现流程完成并成功保存快照后才返回成功。单个来源批次失败仍属于可保存的完成结果，与当前行为一致。

### 6.2 生成报告

```http
POST /api/combined-discovery/reports
Content-Type: application/json
```

请求：

```json
{
  "discovery_id": "8da5...",
  "amount": 10
}
```

校验：

- `discovery_id` 必须是合法 UUID，并对应状态为 `completed` 的快照；
- `amount` 必须是整数，范围为 1–30，默认 10；
- 不接受前端回传整份发现结果，防止篡改和超大请求。

成功响应：

```json
{
  "report_id": "stable-id",
  "discovery_id": "8da5...",
  "requested_amount": 10,
  "returned_amount": 8,
  "generation_mode": "codex",
  "degraded_reason": null,
  "report": {},
  "markdown": "# 机器学习智能发现报告..."
}
```

`generation_mode` 为 `codex` 或 `fallback`。当合格内容少于用户所选信息量时，`returned_amount` 可以更小，响应不是错误。

错误语义：

- `404`：快照不存在；
- `409`：快照状态不完整或文件损坏；
- `422`：参数格式或范围错误；
- `500`：语义生成和确定性降级均失败。

Codex 调用失败但降级成功时返回 `200`，并设置 `generation_mode: "fallback"` 和用户可读的 `degraded_reason`。

## 7. 候选标准化与去重

候选内容只来自快照中 `batches[*].results[*].items[*]`。

每条候选标准化为：

```json
{
  "item_id": "stable-content-id",
  "title": "Python机器学习项目实战",
  "url": "https://example.com/article",
  "normalized_url": "https://example.com/article",
  "source_name": "CSDN",
  "source_key": "csdn.net",
  "summary": "...",
  "hot": "...",
  "existing_relevance": 80,
  "match_type": "关键词匹配",
  "rule_score": 82
}
```

处理顺序：

1. 删除标题为空或 URL 不是有效 HTTP/HTTPS 地址的条目；
2. 规范化 URL 仅用于比较：主机名小写、删除 fragment、删除默认端口、规范路径尾斜杠、排序查询参数，并移除常见追踪参数；
3. 按规范化 URL 去重，保留信息最完整、规则分最高的条目；
4. 对规范化标题做高相似度去重，保留规则分最高条目；
5. 原始展示 URL 始终保留，不使用规范化结果改写用户跳转地址；
6. 使用规范化 URL 与标题生成稳定 `item_id`，同一快照中不可重复。

标题相似度去重采用确定性文本归一化与相似度阈值，不依赖 Codex，避免同一内容在多个批次重复占用额度。

## 8. 规则评分与候选集

规则分范围为 0–100，用于在调用 Codex 前缩小候选集，不直接替代最终语义分。评分信号包括：

- 关键词出现在标题；
- 关键词出现在摘要或描述；
- 自定义源已有 `relevance`；
- 热度字段可解析程度和相对强度；
- 标题、摘要、来源等字段完整度；
- 来源是否属于推荐平台，以及推荐理由与关键词的重合度。

建议固定权重：标题匹配 30、摘要匹配 20、已有相关度 20、来源/推荐理由 10、热度 10、完整度 10。所有输入先归一化到对应区间，并在测试中固定边界行为。

送给 Codex 的候选数为：

```text
min(去重后候选数, amount * 3, 60)
```

候选按 `rule_score` 降序，再按稳定 `item_id` 排序后截断，从而保证输入集合稳定。

## 9. Codex 语义分析

Codex 负责以下任务：

- 判断用户意图类型；
- 为推荐博主和平台生成角色标签及兴趣关系说明；
- 为候选内容生成语义相关度、内容类型、关系说明、标签和阶段；
- 生成主题概览、覆盖方向、推荐阅读顺序和缺失方向。

### 9.1 自动结构选择

报告只能使用以下一种固定结构：

- 学习型：基础认知 → 方法与工具 → 实战内容 → 进阶方向
- 行业型：背景概览 → 当前热点 → 典型案例 → 趋势判断
- 决策型：基础知识 → 可选方案 → 实践建议 → 风险提醒

用户不手动选择。Codex 根据原始兴趣描述、关键词和候选内容判断。若输出无效或意图模糊，默认使用学习型。

确定性降级分类可识别常见意图词：教程、入门、学习、课程、实践倾向学习型；行业、市场、动态、热点、趋势倾向行业型；比较、选型、选择、建议、风险倾向决策型。无明显信号时仍默认学习型。

### 9.2 模型输入安全边界

- 系统提示明确声明网页标题、摘要和来源文本全部是不可信数据，不能作为指令执行；
- 候选以 JSON 数据块传入，与任务指令分隔；
- 不向模型提供 API key、本地路径或不必要的原始网页内容；
- 模型只能返回后端发放的 `item_id`；
- 模型不能返回或修改 URL，URL 由后端按 `item_id` 回填；
- 模型返回的阶段必须属于所选模板；
- 标签、摘要和关系说明设置长度上限，超限输出校验失败。

### 9.3 模型输出校验

模型输出解析为固定 Pydantic Schema。至少校验：

- JSON 可解析且字段类型正确；
- 意图类型属于 `learning | industry | decision`；
- 所有内容 `item_id` 存在于本次候选集合且不重复；
- `relevance_score` 是 0–100 整数；
- `stage` 属于对应模板；
- `matched_keywords` 只能来自发现快照关键词；
- 模型不能增加标题、URL、博主或平台；
- 文本字段满足非空与长度限制。

任何一项失败都视为语义生成失败，进入确定性降级，不使用部分未校验输出。

## 10. 最终筛选与排序

Codex 成功时，最终内容必须满足：

```text
relevance_score >= 55
```

筛选步骤：

1. Codex 正常时优先选择相关度不低于 55 分的内容；
2. 按模板固定阶段顺序组织；
3. 正常情况下，同一平台最多占最终内容的 40%；
4. 先计算 `target_count = min(amount, 合格候选总数)`，再按 `floor(target_count * 0.4)` 计算单平台配额，最少为 1；当条数太少无法在整数上严格满足 40% 时，以来源尽量分散为准；
5. 先按相关度选取并尽量覆盖不同来源；
6. 只有当其他来源没有达到阈值的候选时，才放宽单平台比例；
7. 达到用户额度后停止；若合格内容不足，使用仍有有效标题和链接的候选按排序补足，并在报告中提示低相关内容。

每个阶段内部按以下顺序稳定排序：

1. `relevance_score` 降序；
2. 内容完整度/质量分降序；
3. 可解析热度降序；
4. `item_id` 升序作为最终稳定键。

推荐博主和推荐平台单独展示，不计入 `amount`，也不受 40% 内容来源比例限制。

## 11. 报告数据结构

报告分四层：报告总览、推荐来源概览、适应性阶段路径、精选内容。

```json
{
  "schema_version": 1,
  "title": "机器学习智能发现报告",
  "query": "机器学习",
  "keywords": ["机器学习", "Python"],
  "intent": "learning",
  "structure_name": "学习型",
  "stage_order": ["基础认知", "方法与工具", "实战内容", "进阶方向"],
  "overview": {
    "topic_summary": "...",
    "covered_directions": ["..."],
    "reading_order": "...",
    "missing_directions": ["..."]
  },
  "recommended_sources": {
    "bloggers": [],
    "platforms": []
  },
  "stages": [],
  "warnings": []
}
```

推荐博主：

```json
{
  "name": "示例博主",
  "role_label": "机器学习教学博主",
  "relation_summary": "持续分享机器学习入门、模型训练和 Python 实践内容",
  "matched_keywords": ["机器学习", "Python"],
  "profile_url": "https://..."
}
```

推荐平台使用同样的解释字段，并将 `profile_url` 替换为 `url`。所有链接均由快照原始数据回填。

精选内容：

```json
{
  "item_id": "真实候选ID",
  "title": "Python机器学习项目实战",
  "url": "https://...",
  "source_name": "CSDN",
  "content_type": "实践教程",
  "stage": "实战内容",
  "relation_summary": "通过完整 Python 项目展示机器学习模型训练流程",
  "tags": ["机器学习实战", "Python", "模型训练"],
  "matched_keywords": ["机器学习"],
  "relevance_score": 92,
  "hot": "可选热度信息"
}
```

阶段对象始终按 `stage_order` 输出。没有内容的阶段可以省略看板区块，但 `stage_order` 不变。

## 12. 确定性降级

以下情况触发降级：

- API 网络错误、超时或鉴权错误；
- 模型响应不是合法 JSON；
- Schema、ID、阶段或关键词边界校验失败；
- 模型返回空结果但规则候选存在。

降级报告：

- 使用规则分映射为相关度；
- 使用确定性关键词规则选择结构，模糊时使用学习型；
- 根据标题和摘要中的信号分配阶段；
- 使用命中的关键词和现有推荐理由生成简短关系说明；
- 继续执行相关度排序、40% 来源比例和稳定排序；必要时纳入低相关但有效的候选；
- 总览只总结可验证的关键词、来源数和内容类型；
- 在报告顶部显示“智能总结暂不可用，当前为基础排序报告”。

降级不得编造原始数据中不存在的事实。

## 13. 前端设计

智能发现完成前保持现有输入与进度体验。完成后增加：

### 13.1 视图与工具栏

- 模块内部使用“发现结果 / 展示报告”两个标签页；
- 发现完成后在上方显示报告工具栏；
- 信息量使用分段控件：5、10、20、自定义；
- 自定义选择后显示范围为 1–30 的数字输入；
- “生成展示报告”是明确命令按钮；
- 生成期间禁用重复提交，但不清空发现结果。

### 13.2 状态

- 生成中：显示“清洗结果 → 语义分析 → 组织报告”；
- 成功：自动切换到“展示报告”；
- 降级成功：正常展示报告，同时显示降级提示；
- 失败：停留在当前可用视图并显示错误，可再次生成；
- 用户切回发现结果时，报告状态继续保留。

后端首版是单次同步请求，因此进度条表示当前生成阶段的感知状态，不宣称服务端实时百分比。

### 13.3 报告看板

看板按以下顺序展示：

1. 报告标题、兴趣关键词、结构类型、生成方式和操作按钮；
2. 指标摘要：请求条数、实际条数、覆盖来源数、覆盖阶段数；
3. 总览：主题概览、覆盖方向、推荐阅读顺序、缺失方向；
4. 推荐博主和推荐平台概览；
5. 按固定阶段顺序展示的精选内容。

内容条目突出标题、兴趣关系说明和标签，来源、热度、相关度作为次级信息。点击标题打开原始链接。

### 13.4 导出

- “打印 / 保存 PDF”调用浏览器打印；
- `@media print` 隐藏导航、输入区、标签页和操作按钮，展开全部报告内容；
- “复制 Markdown”复制后端返回的 `markdown`；
- 复制成功或失败提供短暂状态反馈。

桌面端使用适合扫描的分栏信息布局，窄屏降为单列。不得出现文字溢出、报告操作与内容遮挡或卡片嵌套卡片。

## 14. 错误处理与日志

- 快照保存失败：智能发现请求整体失败，日志包含异常但不暴露本地绝对路径给前端；
- 快照不存在或损坏：返回明确的 404/409，不调用 Codex；
- 候选为空：返回成功的空报告，说明没有达到展示条件的内容；
- Codex 失败：记录异常类型和 `discovery_id/report_id`，不得记录 API key 或完整提示内容；
- 报告文件写入失败：不返回虚假的成功；
- Markdown 渲染失败：报告生成整体失败，避免 JSON 与 Markdown 状态不一致；
- 前端报告错误与智能发现错误使用独立状态。

建议日志字段包括：`discovery_id`、`report_id`、请求条数、候选数、合格数、返回数、生成模式、耗时和降级原因分类。

## 15. 测试策略

### 15.1 后端单元测试

- 快照原子保存、读取、不可变性和非法 ID 拒绝；
- URL 规范化、URL 去重、相似标题去重；
- 稳定 `item_id` 和稳定候选排序；
- 规则评分各信号和边界；
- 候选数为 `min(amount * 3, 60)`；
- Codex JSON、未知 ID、重复 ID、非法阶段、越界分数校验；
- 三类结构判断和模糊意图默认学习型；
- Codex 正常时优先 55 分以上内容，fallback 或合格内容不足时允许有效候选进入并显示提示；
- 单平台正常不超过 40%，来源不足时允许放宽；
- 阶段顺序固定、阶段内排序稳定；
- Codex 异常进入降级且不丢失原始链接；
- Markdown 只包含报告已选内容。

### 15.2 API 测试

- 智能发现响应包含 `discovery_id` 且快照已存在；
- 合法报告请求返回 JSON 和 Markdown；
- 相同快照和 amount 复用相同报告；
- 非法 UUID、越界 amount、缺失快照、损坏快照返回约定状态码；
- Codex 失败但降级成功返回 200 和 `generation_mode: fallback`；
- 单个发现批次失败的快照仍可生成报告。

### 15.3 前端验证

- 未完成发现时不允许生成报告；
- 5/10/20/自定义控件与请求参数一致；
- 自定义值限制在 1–30；
- 生成期间防止重复提交；
- 成功后自动切换报告视图；
- 报告失败不会清空发现结果；
- 降级提示、空报告和条数不足状态可见；
- 复制 Markdown 成功/失败反馈正确；
- 打印样式隐藏非报告界面；
- 桌面与移动端无内容重叠或横向溢出；
- 前端构建和现有后端测试继续通过。

## 16. 验收标准

1. 报告只使用指定 `discovery_id` 的已有结果，不触发推荐或爬取。
2. 信息量额度只计算精选内容，博主和平台单独展示。
3. 用户请求 N 条时最多返回 N 条；有效候选不足时返回实际条数，低相关候选会明确标注。
4. 来源充足时任一平台不超过精选内容的 40%。
5. 系统自动选择三种结构之一，模糊意图稳定回退到学习型。
6. 所有内容均说明与关键词的关系，并具有阶段、标签和相关度。
7. 所有标题和链接可追溯到快照原始条目，模型无法添加虚构链接。
8. 相同快照、信息量和报告 Schema 版本重复请求返回同一持久化报告。
9. Codex 不可用时仍能得到基础报告，并清楚显示降级状态。
10. 报告支持页面浏览、浏览器打印/PDF和复制 Markdown。
11. 报告失败不影响原智能发现结果。
